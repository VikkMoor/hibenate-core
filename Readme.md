## Запуск проекта

### 1. Настройка базы данных

Проект использует PostgreSQL, запущенный в Docker-контейнере.

Для подключения к базе данных используются параметры из файла `.env`.

Создайте в корне проекта файл `.env` на основе `.env.example`:

```env
DB_PASSWORD=your_postgresql_password
```

Файл `.env` содержит пароль для подключения к PostgreSQL и не добавляется в Git.

### 2. Настройка Hibernate

Основные настройки подключения к PostgreSQL находятся в:

```text
src/main/resources/hibernate.cfg.xml
```

Пароль базы данных передаётся в Hibernate из переменной окружения `DB_PASSWORD`.

### 3. Запуск отдельного урока

Каждый учебный пример находится в отдельном пакете:

```text
les1
les2
...
```

Для запуска конкретного урока необходимо открыть соответствующий класс `Main`.

Перед запуском в `hibernate.cfg.xml` должна быть указана сущность текущего урока в `<mapping>`.

Например, для урока 1:

```xml
<mapping class="les1.Movie"/>
```

Для урока 2:

```xml
<mapping class="les2.Movie"/>
```

Одновременно регистрировать одноимённые сущности из разных пакетов не следует, поскольку Hibernate использует имя сущности `Movie`.

### 4. Запуск

После настройки `.env`, PostgreSQL и `hibernate.cfg.xml` запустите соответствующий класс `Main` из IntelliJ IDEA.

SQL-запросы Hibernate выводятся в консоль, если в конфигурации включено:

```xml
<property name="hibernate.show_sql">true</property>
```

## Les2. Жизненный цикл Entity

Пакет `les2` содержит пример работы с жизненным циклом JPA Entity в Hibernate.

В примере показаны основные состояния объекта:

- **Transient** — объект создан через `new`, но ещё не связан с Hibernate.
- **Persistent** — объект передан в `session.persist()` и находится под управлением текущей Session.
- **Detached** — Session закрыта, объект больше не связан с Hibernate.
- **Removed** — объект передан в `session.remove()` и будет удалён из базы данных после commit.

В процессе выполнения демонстрируется:

1. Создание нового объекта `Movie`.
2. Сохранение объекта через `session.persist()`.
3. Переход объекта в состояние `detached` после закрытия Session.
4. Изменение detached-объекта без синхронизации с базой данных.
5. Проверка, что изменение detached-объекта само по себе не приводит к `UPDATE`.
6. Возврат объекта под управление Hibernate через `session.merge()`.
7. Синхронизация изменений с базой данных при `commit`.
8. Удаление объекта через `session.remove()`.

В консоли можно увидеть соответствующие SQL-операции Hibernate:

```text
INSERT
SELECT
UPDATE
DELETE
```

Для урока используется отдельная таблица:

```text
movies_les2
```

Это позволяет запускать пример независимо от сущности Movie из предыдущего урока.

## Les3. Связь One-to-One

Пакет `les3` содержит пример связи между сущностями `User` и `UserProfile` с использованием отношения `One-to-One`.

В примере показана двунаправленная связь:

- `UserProfile` хранит внешний ключ на `User`;
- `User` получает доступ к связанному `UserProfile`;
- при загрузке профиля Hibernate подтягивает связанного пользователя;
- при загрузке пользователя Hibernate подтягивает связанный профиль.

Для связи используются аннотации:

```java
@OneToOne
@JoinColumn(name = "user_id", referencedColumnName = "id")
private User user;
```
и:

```java
@OneToOne(mappedBy = "user")
private UserProfile profile;
```

В процессе выполнения демонстрируется:

1. Cохранение пользователя.
2. Сохранение профиля и установка связи с пользователем.
3. Получение профиля вместе со связанным пользователем.
4. Получение пользователя вместе со связанным профилем.
5. Попытка удалить пользователя до удаления профиля и получение ошибки внешнего ключа.
6. Правильное удаление: сначала профиль, затем пользователь.

Для урока используются отдельные таблицы:

```text
users_les3
user_profiles_les3
```

Таблица `user_profiles_les3` содержит внешний ключ `user_id`, который ссылается на `users_les3.id`.

В примере также можно увидеть работу `FetchType.EAGER`, используемого по умолчанию для `@OneToOne`: при загрузке `UserProfile` Hibernate сразу загружает связанную сущность `User`.

Для запуска урока 3 в `hibernate.cfg.xml` должны быть указаны:

```xml
<mapping class="les3.User"/>
<mapping class="les3.UserProfile"/>
```

При этом mapping сущностей предыдущих уроков необходимо временно убрать.

## Les4. Связь Many-to-One и проблема N+1

Пакет `les4` содержит пример связи между сущностями `Post` и `User` с использованием отношения `Many-to-One`.

В примере один пользователь может иметь несколько постов:

```text
User
 ├── Post
 ├── Post
 └── Post
```

Связь реализована в сущности `Post`:

```java
@ManyToOne(fetch = FetchType.LAZY)
@JoinColumn(name = "user_id")
private User author;
```

В таблице `posts_les4` хранится внешний ключ `user_id`, который ссылается на `users_les4.id`.

### EAGER и LAZY

В процессе выполнения рассмотрены две стратегии загрузки связанной сущности:

* `EAGER` — связанная сущность загружается сразу;
* `LAZY` — связанная сущность загружается при первом обращении к ней.

Эксперимент с `EAGER` показал, что `EAGER` не означает обязательное использование `JOIN`. Hibernate может загружать связанную сущность отдельными SQL-запросами.

При `LAZY` связанные пользователи загружались при обращении:

```java
post.getAuthor().getName()
```

### Проблема N+1

N+1 возникает, когда для получения основной коллекции выполняется один SQL-запрос, а затем выполняются дополнительные запросы для связанных сущностей.

Общая схема:

```text
1 SELECT → основная коллекция
N SELECT → связанные сущности
```

В эксперименте с `LAZY` было выполнено:

```text
1 запрос → получение постов
3 запроса → получение трёх разных пользователей
```

### JOIN FETCH

`JOIN FETCH` позволяет загрузить `Post` и связанного `User` в рамках одного запроса.

Hibernate сформировал SQL с `JOIN`:

```SQL
SELECT ...
FROM posts_les4 p
JOIN users_les4 u
    ON u.id = p.user_id
```

После этого обращение к `post.getAuthor()` не вызвало дополнительных `SELECT`, поскольку связанные `User` уже были загружены.

### Основное различие

```txt
EAGER / LAZY
↓
когда загружать связанную сущность

JOIN FETCH
↓
загрузить связанную сущность
в рамках конкретного запроса
```

`EAGER` не гарантирует `JOIN`, а `LAZY` не исключает дополнительные SQL-запросы.

`JOIN FETCH` позволяет явно указать Hibernate, что связанные сущности нужно загрузить вместе с основной сущностью в конкретном запросе.

### Mapping

Для запуска урока 4 в `hibernate.cfg.xml` должны быть указаны:

```xml
<mapping class="les4.User"/>
<mapping class="les4.Post"/>
```

При этом mapping сущностей предыдущих уроков необходимо временно убрать.
